# Forge UI 需求文档

> 状态：持续细化中  
> 当前版本：0.37
> 首次建立：2026-07-28  
> 默认第一用户：内容生产操作者

## 1. 文档定位

本文档是 Forge UI 产品化的长期需求入口。

当前先记录已经确认的产品方向、功能范围、交互需求、可视化需求和待讨论问题。后续每次确认的新需求、范围调整和产品决策，都继续更新到本文档中。

本文档暂不等同于最终设计稿或实施计划。尚未确认的内容应保留为候选需求或待细化项，不能因为被记录在本文档中就自动视为已经批准开发。

## 2. 背景

Forge 当前已经具备多 Agent Case 运行、产物版本管理、审核 Issue、受控返修、交付门禁、人工暂停和崩溃恢复等工程能力。

现有 Web 页面可以创建、运行和恢复 Case，并以泳道形式回放 Turn、路由、工具调用、产物版本、Issue 和门禁结果。但整体仍偏向工程验证和技术回放，尚未形成面向内容生产操作者的完整产品体验。

Forge UI 产品化的目标不是单纯美化现有页面，而是重新组织平台能力，让内容生产操作者能够直接理解和操作一次生产任务。

## 3. 产品定位

Forge UI 是内容生产操作者使用 Forge 的主要操作界面。

它应当优先帮助用户回答以下问题：

1. 我有哪些生产任务？
2. 某个任务现在进行到哪里？
3. 当前由哪个 Agent 或系统环节处理？
4. 已经生成了什么结果？
5. 当前是否存在审核问题或返修任务？
6. 为什么任务暂停、失败或不能交付？
7. 现在是否需要我进行操作？
8. 最终交付结果是什么，依据是否完整？

开发、调试和审计能力仍然保留，但不应占据默认界面的主要位置。

### 3.1 顶层核心对象：生产任务

Forge UI 面向用户的顶层核心对象统一称为“生产任务”。

- 当前由单个模板运行产生的 Case，是一种生产任务；
- 未来由预定义编排流程产生的流程运行，也是一种生产任务；
- 工作台、列表、搜索、筛选、待办和结果都围绕生产任务组织；
- `Case`、`Turn`、`Session` 等术语降为内部执行对象，只在生产详情或高级诊断中出现；
- 后续加入编排器时，不另起一套与生产任务割裂的顶层产品概念。

“生产任务”是用户概念，不要求当前代码立即把 Case 数据表重命名。产品概念与技术对象如何映射，在技术需求阶段单独设计。

## 4. 用户定位

### 4.1 默认第一用户

默认第一用户是内容生产操作者。

该用户需要创建任务、观察生产进度、查看结果、理解审核问题、处理人工介入和获取最终交付，但不应被要求理解数据库、执行租约、内部消息协议或其他平台实现细节。

### 4.2 次级用户

次级用户包括：

- 模板维护者；
- Forge 开发人员；
- 运行与故障排查人员；
- 需要审计生产证据的管理者。

次级用户所需的原始上下文、工具调用、哈希、内部 ID 和控制事件，应放入高级视图或诊断视图。

当前阶段不建设登录鉴权、角色权限或按身份隐藏功能。默认用户和次级用户只用于决定信息优先级，不构成访问权限：

- 所有使用者都可以找到并使用产品已提供的功能；
- 常用生产能力默认直接展示；
- 高级功能和诊断信息通过高级配置、展开区或二级入口提供；
- 不设置改变整个产品界面形态的全局“高级模式”开关；
- 高级入口应可发现，但不干扰不需要它的用户完成常规任务；
- 不做鉴权不代表可以绕过状态机、门禁、安全校验或脱敏要求；
- 未来如引入多用户协作，再单独设计身份、角色和权限模型。

## 5. 产品目标

### 5.1 核心目标

- 让内容生产操作者能够从 UI 创建并运行 Forge 任务；
- 让用户快速判断任务状态、当前进度和下一步行动；
- 让产物、审核、Issue、返修和门禁形成连贯的产品体验；
- 让异常、暂停和恢复具有明确、可信的交互；
- 让 UI 展示的状态与 Forge 真实持久化状态保持一致；
- 为后续预定义编排流程 UI 预留一致的产品概念和界面扩展空间。

### 5.2 非目标

当前不以以下事项为目标：

- 自由拖拽和任意连线的流程设计器；
- 在默认用户界面中暴露全部工程字段；
- 允许用户手工修改 Case、Issue、版本或门禁状态；
- 在当前阶段通过 UI 编辑或人工修订产物内容；
- 当前阶段的登录鉴权、角色权限和多用户访问控制；
- 通过第一版 UI 管理 Provider API Key、Endpoint 或其他连接凭据；
- 应用内通知中心、未读通知体系和邮件、短信、即时通讯等站外推送；
- 第一版产物的 Word、PDF 转换和多产物批量打包；
- 第一版手机端的完整创建、运行、执行记录和诊断体验；
- 用前端临时状态代替 Forge 的真实运行状态；
- 在后台能力尚未成立时制作不可运行的“演示型 UI”；
- 把知乎故事等具体业务写死进通用 UI。

## 6. 产品信息分层

Forge UI 的信息分为三层。

### 6.1 用户层

默认直接展示：

- 任务名称和用途；
- 当前状态和生产进度；
- 当前处理者；
- 当前产物；
- 待处理事项；
- 阻塞原因；
- 最终结果。

### 6.2 生产层

在任务详情的二级视图中按需展示：

- Agent 协作过程；
- Turn 和消息路由；
- 产物版本；
- 审核结果和 Issue；
- 返修指令和修改范围；
- 交付门禁；
- 恢复和人工介入记录。

### 6.3 诊断层

默认折叠，任何使用者需要时都可以主动进入高级视图查看：

- Case、Turn、Session、Message 等内部 ID；
- 脱敏后的原始工具参数和工具结果；
- 脱敏后的上下文快照；
- provider 错误；
- 控制事件；
- 内容哈希和模板身份；
- 数据库来源和执行租约信息。

API Key、runner token 和其他凭据在任何层级都不得录入、展示或回显。

### 7.1 第一版页面与导航

第一版主导航只保留两个核心入口：

1. **工作台**：任务状态摘要、统一任务列表、搜索、筛选和任务管理；
2. **模板中心**：理解、选择和查看生产模板。

其他页面和功能从对象上下文下钻：

- “新建生产任务”作为全局显著操作，进入三步创建流程；
- 任务列表进入任务详情，任务详情默认展示生产概览，并下钻到产物、Issue、返修、门禁、执行记录和诊断；
- 模板中心进入模板详情，并可直接发起新任务；
- 归档任务和草稿回收站作为工作台的筛选范围或二级视图，不占用主导航；
- Provider/Model 目录与连接状态从模型选择器、模板详情或创建任务高级配置进入，不占用主导航；
- 不为每一种 Case 状态单独建立页面；
- 未来内置预定义编排器时，再在主导航增加“流程”入口。

## 8. 功能域需求

### UI-FR-001 工作台

工作台是用户进入 Forge 后的默认入口。

已经确认：首页首先服务于继续处理已有生产任务，而不是以模板选择或新建表单作为默认主体。

工作台的信息优先级为：

1. 需要人工处理的任务；
2. 异常或被阻塞的任务；
3. 正在运行的任务；
4. 最近更新和最近完成的任务。

工作台采用“状态摘要卡 + 统一任务列表”的信息架构：

- 顶部状态摘要卡展示人工待办、异常阻塞、运行中和已完成任务数量；
- 点击摘要卡后，以对应状态条件筛选下方统一任务列表；
- 统一列表承载当前范围内的所有任务，不为不同状态维护彼此割裂的多套列表；
- 默认按处理优先级和最近更新时间排序，并允许用户调整筛选和排序；
- 不提供可拖拽状态看板，任务状态只能由 Forge 的真实状态机改变；
- UI 筛选、排序或查看任务不能修改任务的生产状态。

“新建生产任务”需要作为工作台上的显著入口，但不能挤占当前待办和运行状态的主要注意力。

当前阶段不建设通知体系。需要人工输入、异常阻塞、恢复就绪和完成交付等变化，统一通过生产任务的持久化状态表达：

- 工作台按状态优先级组织任务，不生成独立通知或未读记录；
- 任务列表提供状态筛选、排序和数量摘要；
- 任务详情通过当前状态、阶段和横幅解释需要处理的事项；
- 状态变化应自动反映到工作台、列表和详情页；
- 用户通过主动查看任务状态了解进展；
- 不建设应用内通知中心，也不发送邮件、短信、企业微信或其他站外通知。

候选功能：

- 展示运行中、等待人工、异常、已完成任务数量；
- 按任务状态展示需要用户处理的任务；
- 展示最近创建和最近更新的任务；
- 提供任务搜索和常用筛选；
- 从工作台快速进入创建任务或任务详情；
- 后续支持展示预定义编排流程运行。

主要交互：

- 按状态、模板、环境和时间筛选；
- 搜索任务名称或标识；
- 点击待办直接进入需要处理的位置；
- 快速创建新任务。

适合的可视化：

- 状态统计卡；
- 可筛选、可排序的统一任务列表；
- 当前筛选条件和任务状态标识。

### UI-FR-002 模板中心

模板中心帮助用户理解 Forge 当前可以完成哪些生产任务。

模板中心采用卡片、详情和高级展开三层信息：

模板卡片默认展示：

- 模板名称和一句话用途；
- 所需输入摘要；
- 预期产物类型；
- Agent 数量；
- 当前可用版本；
- 可用、不可用或校验异常状态；
- “使用此模板创建任务”入口。

模板详情进一步展示：

- 完整用途和使用说明；
- 输入字段结构、必填项和说明；
- 预期产物及其类型；
- Agent 名称、职责、模型和协作关系；
- 模板版本历史、版本差异和校验状态；
- 不可用或校验异常时的可理解原因。

高级展开区展示原始 YAML、模板内容哈希、来源身份和详细校验结果。高级信息默认折叠，且仍不得包含任何 Provider 凭据或其他秘密。

模板版本遵循以下产品规则：

- 从模板中心创建全新任务时，默认使用该模板最新的可用版本；
- 草稿始终保留已选择的模板版本，不因模板更新而静默升级；
- 草稿存在更新版本时，显示“有新版本可用”，由用户主动查看差异并确认是否升级；
- 基于已有任务创建新任务时，默认保留来源任务的模板版本，同时提供切换到新版本的入口；
- 切换模板版本后必须重新校验输入和运行配置，不能把不兼容变化静默带入任务；
- 任务启动时冻结准确的模板版本，运行、暂停、恢复和终态查看都继续引用该版本；
- 模板版本绑定、兼容性判断和差异计算方式在技术需求阶段确定。

候选功能：

- 查看模板名称、用途和说明；
- 查看模板需要的输入；
- 查看模板包含的 Agent 及其职责；
- 查看模板产出的正式产物类型；
- 查看模板版本和校验状态；
- 查看模板版本差异；
- 查看草稿可用的模板更新；
- 从模板直接创建任务。

主要交互：

- 搜索、筛选和选择模板；
- 查看模板详情；
- 根据模板发起任务；
- 通过高级视图查看模板原始配置和校验结果。

适合的可视化：

- 模板卡片；
- Agent 角色关系；
- 输入到产物的简单关系图。

### UI-FR-003 创建任务

创建任务应当由模板配置驱动，不为具体业务写死表单。

已经确认创建任务支持两种完成方式：

- 主操作“创建并运行”：保存任务并立即进入生产；
- 次操作“保存草稿”：保存当前输入，稍后继续补充或启动。

草稿需要作为工作台和任务列表中的明确状态展示，用户可以重新进入草稿继续填写。

创建任务采用三步引导：

1. **选择模板**：理解模板用途、所需输入和预期产物，并选择本次任务使用的模板；
2. **填写内容输入**：根据模板 `input_fields` 动态生成表单，填写任务名称和生产所需内容；
3. **确认配置并启动**：汇总模板、输入、运行环境和每个 Agent 的模型，确认后创建并运行。

模型、运行环境等配置在第三步以摘要形式可见。默认使用模板和系统默认值，需要修改时再展开高级配置；高级配置不得隐藏本次任务实际会使用的模型和环境。

“创建并运行”是第三步的主操作，“保存草稿并退出”作为次操作保留。

草稿采用自动保存和手动保存相结合：

- 用户填写或修改草稿时自动保存；
- 页面持续显示“保存中”“已保存”或“保存失败”，并显示最近一次成功保存时间；
- 自动保存失败时保留当前页面内容，提供明确提示和重试入口；
- “保存草稿并退出”负责显式保存当前内容并返回工作台或任务列表；
- 只有存在未成功保存的内容时，离开页面才需要提醒用户；
- 不得在未提示用户的情况下丢弃未保存内容；
- 自动保存的触发时机、并发冲突和失败重试机制在技术需求阶段确定。

任务输入遵循以下生命周期规则：

- 草稿阶段允许修改输入；
- 任务一旦启动，本次任务的原始输入立即冻结；
- 运行中和终态任务都不允许原地修改输入；
- 用户需要修改输入时，使用“基于此任务创建新任务”；
- 新任务复制原任务输入并允许用户修改；
- 原任务、原输入、产物和审核证据完整保留；
- 新旧任务之间需要保留可查询的来源关系。

“基于此任务创建新任务”采用受控预填：

- 预填原任务使用的模板版本、原始输入、标签、模型覆盖和运行环境；
- 所有预填内容在新任务的草稿阶段允许修改；
- 不复制原任务的运行状态、产物、Issue、返修、门禁、执行事件或内部执行 ID；
- 新任务明确记录并展示其来源任务，原任务也能查看由其派生的新任务；
- 新任务必须重新经过创建流程的配置确认步骤才能启动；
- 复制和来源关系的持久化方式在技术需求阶段确定。

候选功能：

- 选择模板；
- 根据 `input_fields` 动态生成输入表单；
- 填写任务名称；
- 选择允许的运行环境和模型模式；
- 显示必填项和输入错误；
- 在启动前展示任务摘要；
- 创建后自动进入任务详情。
- 基于已有任务预填可编辑配置并创建新任务。

主要交互：

- 分组填写字段；
- 长文本输入；
- 文件或素材输入能力后续单独确认；
- 查看草稿保存状态；
- 保存草稿并退出；
- 创建并启动；

### UI-FR-004 任务管理

任务管理覆盖 Case 列表和 Case 生命周期操作。

第一版采用扁平的生产任务列表，不要求用户先创建项目或工作空间。

任务组织方式包括：

- 搜索；
- 状态、模板、环境和时间筛选；
- 排序；
- 标签。

标签采用自由创建和复用建议相结合：

- 用户可以输入并创建新的任务标签；
- 输入时搜索已有标签并提供匹配建议，便于复用一致名称；
- 标签仅用于任务组织、搜索和筛选，不改变任务输入、运行状态或执行行为；
- 状态、模板、环境和时间继续使用独立的结构化字段与筛选器，不由标签代替；
- 第一版不建设独立的标签管理后台、审批流程或固定标签体系；
- 标签规范化、重名判断和数量限制在技术需求阶段确定。

项目或工作空间仅作为未来可选分组能力保留，不进入第一版必需范围。后续即使增加分组，生产任务仍保持为顶层核心业务对象，项目只负责组织任务。

任务归档和删除遵循以下规则：

- 所有状态的任务都支持归档和取消归档；
- 归档只影响默认列表中的可见性，不修改任务状态和生产证据；
- 默认任务列表、状态摘要和搜索结果只包含未归档任务；
- 用户可以开启“包含归档”扩展当前搜索，也可以进入“已归档”筛选只查看归档任务；
- 搜索词、状态、模板、环境、标签和时间条件在包含归档时继续生效；
- 归档任务保留归档前后的真实生产状态、产物和全部证据；
- 归档视图中的任务只提供查看、取消归档和“基于此任务创建新任务”；
- 草稿任务可以移入回收站；
- 回收站中的草稿从默认任务列表隐藏，但可以通过工作台筛选进入；
- 用户可以从回收站恢复草稿，恢复后继续编辑或启动；
- 第一版不自动永久删除回收站草稿；
- 第一版不提供“永久删除”或“清空回收站”操作；
- 任务一旦启动，当前 UI 不提供永久删除，只能归档；
- 已启动任务的输入、产物、Issue、返修、门禁和审计证据必须保留；
- 回收站保留期限、管理员级永久清理和数据保留策略留到技术与运维需求阶段讨论。

运行中任务的人工控制遵循以下规则：

- 同时提供“暂停”和“停止”；
- 暂停是在系统确认的安全边界停止继续执行，之后允许恢复；
- 暂停是运行中任务更常用、更安全的控制操作；
- 停止会把任务结束为终态，不能原地继续；
- 停止必须二次确认，并明确说明影响；
- 暂停和停止都不删除已经完成的 Turn、产物、Issue、门禁或审计证据；
- 安全暂停边界、当前 Turn 的处理和恢复语义在技术需求阶段确定。

任务异常后的可恢复性由系统根据执行证据判定，而不是交给用户盲目选择：

- 可安全恢复的任务进入等待恢复状态，并提供“从中断处恢复”；
- 不可安全恢复的任务进入失败终态，仅提供“基于此任务创建新任务”；
- UI 应解释系统的判定结果、异常发生位置以及已经保留的证据；
- 不提供强制重试、强制恢复或跳过证据校验的操作；
- 具体判定条件、幂等边界和恢复机制在技术需求阶段确定。

候选功能：

- 查看全部可访问任务；
- 按状态、模板、环境和时间筛选；
- 按自由标签筛选；
- 搜索任务；
- 查看任务更新时间、当前阶段和结果摘要；
- 启动尚未运行的任务；
- 暂停正在运行的任务；
- 恢复已暂停的任务；
- 停止允许停止的任务；
- 从系统判定的安全中断处恢复任务；
- 明确终态任务不可继续运行；
- 基于已有任务创建新任务；
- 后续确认归档、删除和批量操作是否需要。

主要交互：

- 搜索和组合筛选；
- 排序；
- 分页或增量加载；
- 状态相关操作菜单；
- 归档、取消归档和查看归档任务；
- 搜索时切换是否包含归档任务；
- 草稿移入回收站；
- 查看回收站并恢复草稿；
- 危险操作确认。

### UI-FR-005 任务概览

任务概览是生产任务详情的默认首屏。详情页首先回答“任务进行到哪里、现在需要做什么、当前结果是什么”，不直接把 Agent 执行过程作为主视图。

必须优先展示：

- 任务名称和模板；
- 当前 Case 状态；
- 当前处理者或等待对象；
- 阶段与步骤进度；
- 当前有效产物；
- 未解决 Issue 数量；
- 当前是否处于返修；
- 最新门禁状态；
- 是否需要人工操作；
- 最近一次重要事件。

任务概览应提供到当前产物、阻断 Issue、返修和门禁证据的快捷入口，但不在首屏展开完整执行细节。

Agent 泳道、Turn、消息路由、工具调用和原始运行证据统一进入二级“执行记录”视图。用户可以从概览中的状态、事件或异常定位到对应执行记录。

任务概览不应要求用户先阅读完整泳道或执行日志才能判断任务状态。

任务进度遵循以下产品规则：

- 以模板定义的阶段和步骤为基础，不在通用 UI 中写死业务阶段；
- 每个步骤展示已完成、进行中、等待或阻塞等离散状态；
- 明确标识当前阶段、当前步骤和可执行的下一步；
- 第一版不展示缺乏可靠依据的完成百分比或预计完成时间；
- 发生重复审核或返修时，单独展示当前轮次和历史轮次；
- 阶段、步骤与内部 Case 状态、Turn 的映射规则留到技术需求阶段确定。

适合的可视化：

- 任务状态条或阶段进度条；
- 当前处理节点；
- 结果、Issue、返修和门禁摘要卡；
- 阻塞横幅。

### UI-FR-006 Agent 协作过程

该功能位于任务详情的二级“执行记录”视图，用于解释一次生产任务内部发生了什么，不作为进入任务详情后的默认主视图。

“执行记录”采用一个联动界面：

- 主体区域展示 Agent 泳道、Turn、调用顺序、消息路由、工具行为和产物生成过程；
- 右侧栏展示产物演进链，把产物版本、版本状态、版本 Diff、关联 Issue、返修指令、返修版本和验证结果组织在同一条链上；
- 产物演进链应突出当前有效版本、最新工作版本、被拒绝或已替代版本以及最终交付版本；
- 选择主体中的 Agent、Turn 或产物生成事件时，右侧栏定位并高亮相关产物节点；
- 选择右侧栏中的版本、Issue、返修或验证节点时，主体定位并高亮对应 Agent 和 Turn；
- 完整正文继续使用产物阅读模式，完整版本比较继续使用并排或差异视图；右侧栏负责展示关系、状态和进入这些视图的入口；
- 在较窄的桌面窗口中，右侧产物演进链收为可打开的抽屉；
- 任务概览仍是详情默认首屏，执行记录界面不取代已确认的生产概览。

候选功能：

- 展示模板中配置的 Agent；
- 展示每个 Agent 的名称、职责、模型和会话策略；
- 展示 Turn 顺序和状态；
- 展示 Agent 之间的消息路由；
- 展示每个 Turn 产生的产物或工具行为；
- 展示失败 Turn 和 provider 错误；
- 支持从 Turn 跳转到右侧产物演进链中的相关版本、Issue 或返修节点。

主要交互：

- 展开或折叠 Turn；
- 查看 Turn 输入和输出；
- 查看工具行为摘要；
- 联动选中 Agent 生产事件和产物演进节点；
- 通过当前 Turn 的高级展开区查看原始工具参数和上下文。

适合的可视化：

- Agent 泳道；
- 时间线；
- 路由箭头；
- Turn 状态和耗时；
- 右侧产物演进链。

### UI-FR-007 产物与版本

产物是 Forge 产品体验中的核心对象。

在“执行记录”视图中，产物版本及其状态、Diff、Issue、返修和验证结果统一进入右侧产物演进链；在任务概览和产物阅读模式中，仍以当前有效版本为主要结果。

任务详情的主结果区域默认展示系统判定的当前有效版本，不按创建时间简单选择最新版本：

- 当前有效版本是用户默认阅读、复制和导出的主结果；
- 最新创建的工作版本单独标识，并明确显示其审核或返修状态；
- under_review、rejected、superseded 等版本不得覆盖当前有效版本；
- 如果任务尚未形成当前有效版本，主结果区域应明确说明，并可提供带状态标识的最新工作版本预览；
- 用户切换浏览历史版本不改变系统记录的当前有效版本；
- delivered 版本作为最终交付结果单独突出展示；
- 当前有效版本的系统判定规则在技术需求阶段确定，普通 UI 不提供绕过状态和门禁的手工提升操作。

当前阶段的产物界面是只读生产结果界面，支持查看、比较、复制、下载和导出，不提供正文编辑或创建人工修订版本。人工修订能力作为后期候选需求保留；未来如引入，仍必须以新增版本实现，不得覆盖既有产物。

第一版产物复制与下载遵循以下范围：

- 支持把当前查看版本的正文复制到剪贴板；
- 支持下载纯文本 `.txt`；
- 支持下载 Markdown `.md`；
- 如果模板明确声明产物的原始文件类型，则保留并提供该原始类型；
- 第一版不提供 Word、PDF 等排版格式转换；
- 第一版不提供多个产物或多个版本的批量打包下载；
- 复制和下载不改变产物版本、审核状态或交付状态；
- 文件命名、字符编码和模板原始类型映射在技术需求阶段确定。

长篇文本产物默认使用专门的只读正文阅读模式：

- 正文采用适合连续阅读的行宽、字号、行距和段落间距；
- 保留原始段落、换行和标题层级，不使用代码块作为默认展示容器；
- 支持在当前产物内全文搜索；
- 根据标题或模板提供的结构生成章节定位入口；
- 版本、来源、哈希等详细元数据默认折叠，但当前版本状态始终清晰可见；
- 正文不放入可编辑文本框，不产生可修改产物的暗示；
- 用户发起版本比较时切换到并排或差异视图，退出比较后回到正文阅读模式；
- 超长文本的渲染、搜索索引和章节识别方式在技术需求阶段确定。

候选功能：

- 展示当前有效产物；
- 单独展示最新工作版本及其状态；
- 展示所有历史版本；
- 区分 draft、under_review、approved、rejected、superseded、delivered 等状态；
- 展示版本父子关系；
- 展示版本摘要和创建来源；
- 使用正文阅读模式查看长篇内容；
- 在当前产物中搜索并按章节定位；
- 选择任意两个版本比较；
- 复制产物正文；
- 下载纯文本、Markdown 或模板声明的原始类型；
- 从版本跳转到相关审核、Issue、返修和门禁。

主要交互：

- 切换版本；
- 选择比较基准；
- 查看完整内容；
- 复制正文或下载允许的文件类型；
- 跳转到版本相关证据。

适合的可视化：

- 版本链；
- 版本状态；
- 行级或块级 Diff；
- 当前有效版本、最新工作版本和最终交付版本的明确区分。

### UI-FR-008 审核与 Issue

- 从 Issue 查看关联返修指令和修复版本；

主要交互：

### UI-FR-010 交付门禁

交付门禁必须明确表达“交付是系统决定，不是 Agent 声明”。

候选功能：

- 展示最新门禁结果；
- 展示历史门禁结果；
- 独立展示五项检查；

### UI-FR-012 异常与恢复

异常与恢复应让用户知道发生了什么、系统保留了什么、现在可以做什么。

### UI-FR-013 审计与诊断

审计与诊断属于高级功能，默认折叠，但当前阶段不以权限限制其入口。

诊断视图展示 Forge 已经持久化且允许披露的执行证据：

- Case、Turn、Session、Message、工具行为和路由边等内部 ID 与关联关系；
- 完整 Turn 状态和已持久化消息内容；
- 脱敏后的工具名称、调用参数、执行结果和错误；
- 脱敏后的上下文快照；
- Provider、模型、响应状态和脱敏后的 Provider 错误；
- 模板、输入、产物版本的身份、内容哈希和来源；
- 数据库来源、执行租约和控制事件；
- 人工输入、暂停、恢复、停止和门禁等审计事件。

诊断视图遵循严格的信息边界：

- 只展示 Forge 实际持久化的证据，不生成或推测缺失的运行信息；
- 永不展示模型隐藏思维链或内部推理；
- 永不展示 API Key、Token、Authorization Header、Cookie、连接凭据或其他秘密；
- 工具参数、工具结果、上下文和错误信息必须先经过脱敏；
- 被脱敏字段应显示明确占位符，使用户知道信息被安全隐藏，而不是伪装为空值；
- 复制诊断信息时继续使用相同或更严格的脱敏规则；
- 具体脱敏规则、敏感字段检测和诊断数据体积控制在技术需求阶段确定。

候选功能：

- 查看完整 Turn；
- 查看消息；
- 查看工具调用参数和结果；
- 查看上下文快照；
- 查看 route edge 和 control event；
- 查看 provider 错误；
- 查看模板、输入和产物身份；
- 复制脱敏后的诊断信息。

诊断视图必须继续遵守不泄密要求。

### UI-FR-014 环境管理

Forge 当前区分 production、test 和 all。

环境能力当前不做权限隔离，任何使用者都可以通过高级入口访问：

- 默认生产界面使用 production；
- test 作为可选运行环境放在高级配置中；
- all 是 production 与 test 的只读聚合查看范围，不是可启动任务的运行环境；
- production、test 和 all 都需要明确的环境标识；
- all 中的写操作由系统禁用并解释原因，这属于环境语义而不是鉴权限制；
- 环境切换和危险操作仍需明确反馈或二次确认。

候选功能：

- 明确展示当前环境；
- 切换 production、test 和 all；
- `all` 作为只读聚合视图；
- 在不同环境使用明显但不过度干扰的视觉标识；
- 在只读环境禁用写操作并解释原因；
- 危险操作前再次确认目标环境。

### UI-FR-015 Agent 模型配置

Forge UI 需要让用户看到每个 Agent 使用的模型，并允许在受控范围内修改。

已经确认的需求：

- UI 展示当前可用的 Provider 和模型目录；
- UI 展示 Provider 的连接状态和模型可用状态；
- 连接状态只表达已配置、未配置、可用或异常等结果，不展示任何凭据内容；
- 用户可以从可用目录中为模板 Agent 或任务草稿选择 Provider 和 Model；
- 模板详情展示每个 Agent 配置的模型；
- Case 详情展示每个 Agent 在该次运行中实际使用的模型；
- UI 支持修改 Agent 的模型选择；
- 模板维护者可以修改 Agent 的默认模型，修改只影响之后创建的任务；
- 任务处于草稿阶段时，用户可以基于模板默认值覆盖本次任务的 Agent 模型；
- 任务启动时冻结每个 Agent 的实际运行模型；
- 运行中和终态任务不允许直接更换模型；
- 已启动任务需要更换模型时，基于原任务创建新任务；
- Case 恢复和续跑默认继续使用启动时冻结的原模型；
- 模板默认模型、任务草稿覆盖值和任务实际运行模型需要明确区分并可查询；
- 模板中声明的 `agent.model` 必须真正控制 Pi Agent Session 使用的模型，不能只作为展示字段；
- Forge 负责解析、传递并记录最终生效的模型；
- 模型提供商适配、模型调用和 Agent Runtime 继续复用 Pi 的能力；
- Provider API Key、Endpoint 等连接配置继续由服务端环境或部署配置管理；
- 第一版 UI 不提供 Provider 凭据的录入、编辑、查看、复制或回显；
- Provider 凭据不写入模板，也不在任何 UI 中展示；
- 不允许把 API Key 等凭据记录到 Case、日志或前端数据中。

需要在详细设计时确定：

- 可选模型列表由 Pi Runtime 动态提供，还是由 Forge 维护允许列表；
- 模型不可用、Provider 未配置或恢复时原模型缺失的处理方式；
- Provider/Model 目录和连接状态在相关模型选择上下文中的具体呈现方式。

主要交互：

- 在模板 Agent 列表中查看模型；
- 使用 Provider 和 Model 两级受控选择器更换模型；
- 查看 Provider 连接状态和模型可用状态；
- 创建任务时查看本次任务将使用的模型；
- 明确标记“跟随模板”或“本次覆盖”；
- 修改前说明影响范围；
- 模型不可用时给出可操作的错误提示。

适合的可视化：

- Agent 卡片中的 Provider/Model 标签；
- 模板默认模型与本次实际模型的差异标记；
- 模型或 Provider 不可用状态。

## 9. Case 状态与用户动作

下表记录当前状态对应的产品表达方向，后续需要逐项确认。

| Case 状态 | 用户应看到的含义 | 候选操作 |
|---|---|---|
| created | 草稿或已创建待启动 | 继续编辑、查看输入、启动、移入回收站或归档 |
| running | 正在生产 | 查看进度、查看当前 Agent、暂停、停止 |
| paused | 已由用户安全暂停 | 查看暂停位置、恢复、停止 |
| waiting_review | 等待或正在审核 | 查看待审核版本和审核进度 |
| repairing | 正在返修 | 查看 Issue、返修范围和修改进度 |
| waiting_recovery | 系统判定可安全恢复 | 查看中断原因和已保留证据、从中断处恢复 |
| waiting_human | 等待人工输入 | 阅读问题、提交回答、恢复 |
| approved | 系统门禁通过 | 查看、复制或导出最终产物 |
| failed | 系统判定不可安全恢复的运行失败 | 查看错误和证据、基于此任务创建新任务 |
| stopped | 已停止 | 查看停止原因和已有证据、基于此任务创建新任务 |

## 10. 重点可视化需求

### UI-VR-001 Case 状态与进度

采用模板驱动的阶段步骤视图，展示已完成、进行中、等待和阻塞状态。用户无需阅读日志即可判断当前阶段、当前步骤和下一步。

第一版不使用缺乏确定计算依据的百分比或预计完成时间。审核、返修等循环过程应展示轮次，而不是把重复执行伪装成线性百分比。

### UI-VR-002 Agent 泳道或协作时间线

在二级“执行记录”视图的主体区域展示 Agent、Turn、路由、返修和交付过程；右侧产物演进链与主体选择状态联动，并支持从生产概览中的相关状态或事件进入。

### UI-VR-003 产物版本链

在执行记录右侧栏展示版本父子关系以及有效、审核中、拒绝、替代和交付状态，并串联相关 Diff、Issue、返修与验证节点。默认突出当前有效版本，最新工作版本和最终交付版本使用不同标识。

### UI-VR-004 版本 Diff

展示版本之间的内容变化，并支持用户选择比较版本。比较是从正文阅读模式主动进入的独立视图，支持并排或差异展示，不取代默认阅读体验。

### UI-VR-005 返修范围

展示 editable、frozen、changed 和 scope violation。

### UI-VR-006 Issue 生命周期

展示 Issue 从发现、返修、声称修复到验证关闭的过程。

### UI-VR-007 Issue、返修和版本关系

作为右侧产物演进链的一部分，帮助用户理解一个问题在哪个版本被发现、由哪条返修指令处理、在哪个版本被修复，以及最终如何验证。

### UI-VR-008 交付门禁

展示五项门禁检查及其阻断来源。

### UI-VR-009 异常与恢复时间线

展示暂停、失败、恢复和人工介入等重要控制事件。

### UI-VR-010 模板 Agent 关系

帮助用户理解模板中有哪些 Agent，以及它们如何协作。

## 11. 重点交互需求

### UI-IR-001 渐进式披露

默认展示业务结论，工程细节通过与当前对象相关的展开区、抽屉或二级视图访问。

高级功能采用上下文入口，不设置全局“高级模式”：

- Agent 模型和运行环境从创建任务的高级配置进入；
- 执行记录和运行诊断从任务详情进入；
- 模板原始配置和校验详情从模板详情进入；
- 某个高级区域的展开或收起不改变其他页面的展示状态或功能语义；
- 入口名称应说明能查看或修改什么，避免使用含义模糊的单一“高级模式”按钮。

### UI-IR-002 状态驱动操作

页面只提供当前状态允许执行的操作，不展示无效或危险按钮。

### UI-IR-003 跨对象跳转

Issue、返修、版本、Turn 和门禁之间必须能够互相定位。在执行记录界面中，主体 Agent 生产事件与右侧产物演进节点采用双向选中和高亮，不要求用户离开当前界面拼接因果关系。

### UI-IR-004 明确反馈

创建、启动、停止、恢复和提交人工输入后，应明确显示操作是否被接受以及系统当前状态。

编辑草稿时应持续显示保存状态和最近一次成功保存时间；保存失败不能伪装为已保存。

### UI-IR-005 危险操作确认

停止、重试、失效或其他可能影响已有生产结果的操作，需要说明影响范围并二次确认。

### UI-IR-006 空状态和异常状态

无任务、无产物、无 Issue、无门禁记录、读取失败等情况需要有明确解释和下一步入口。

### UI-IR-007 自动刷新

运行中任务需要自动更新。waiting_human、异常、恢复和交付等状态变化应直接更新工作台、任务列表和任务详情，不依赖通知系统。

实时更新采用条件跟随：

- 新状态、Turn、工具事件、产物版本和 Issue 应增量进入当前界面，不触发整页刷新；
- 当用户位于执行记录的最新位置时，主体 Agent 过程和右侧产物演进链自动跟随最新进展；
- 当用户正在查看历史 Turn、旧版本、Issue、返修节点或 Diff 时，保持当前滚动位置、选择和展开状态；
- 查看历史期间出现新内容时，只在当前界面显示“有新进展”入口，不自动把用户拉回最新位置；
- 用户点击“有新进展”后，主体与右侧产物演进链一起定位到最新状态；
- 任务总体状态和危险阻断仍应更新，但不得破坏用户正在阅读的历史上下文；
- “有新进展”是当前任务内的上下文入口，不形成独立通知或未读通知体系；
- 具体采用轮询、流式事件或其他机制，以及断线重连策略，在技术设计阶段决定。

### UI-IR-008 长内容阅读

故事、文案、提示信息和上下文可能很长。产物正文使用只读阅读模式，提供舒适行宽、段落排版、全文搜索和章节定位；详细元数据默认折叠。版本比较时再切换到并排或差异视图。

### UI-IR-009 桌面端布局范围

第一版只以桌面和常见笔记本设备作为正式产品目标：

- 宽桌面下，执行记录保持 Agent 生产主体与右侧产物演进链同时可见；
- 较窄的桌面窗口下，右侧产物演进链收为抽屉，主体区域保持可用；
- 工作台、模板中心、三步创建流程、任务详情、正文阅读和诊断都需要在常见笔记本宽度下可完成；
- 第一版不针对手机设计完整的信息架构和操作流程；
- 手机或极窄屏只保证基础内容不会完全不可读，不纳入创建、运行和诊断的产品验收范围；
- 具体断点、最小支持宽度和抽屉行为在视觉与技术设计阶段确定。

## 12. 产品体验原则

- 默认面向内容生产操作者，而不是数据库或 Agent 框架开发者；
- 当前阶段不靠权限隐藏高级功能，而是通过渐进式披露控制信息复杂度；
- 先展示结论，再展示证据；
- 状态名称需要有用户可理解的中文表达，同时允许高级视图查看原始状态值；
- 所有关键状态必须来自 Forge 持久化数据；
- 生产任务启动后输入冻结，任何输入变更都通过创建新任务实现；
- 用户应当随时知道当前任务是否仍在运行；
- 阻塞状态必须同时说明原因和可执行的下一步；
- 产物、Issue、返修和门禁不能被拆成彼此孤立的信息区；
- 任何使用者都不能通过 UI 绕过状态机和门禁；
- UI 必须保持模板和业务无关；
- 高级诊断信息必须脱敏。

### 12.1 视觉语言

第一版采用用户提供的 Claude Design 风格截图作为视觉方向参考，但不照搬截图中的具体布局和组件。整体应呈现温暖、克制、安静且具有编辑器质感的桌面生产工具：

- 使用暖陶土色或珊瑚橙作为环境背景与品牌强调色，主工作区使用米白、暖白和浅灰；
- 页面、侧栏、卡片和浮层采用较大的统一圆角、细边框与低对比度柔和阴影，建立清晰但不厚重的层级；
- 主操作使用黑色或近黑色实底与白色文字，选中态和次级强调可使用克制的珊瑚橙；
- 按钮、筛选器和分段选择器保持紧凑圆润，避免过度装饰；
- 正文与标题使用深炭色，标题层级清晰；辅助栏目标题可使用小字号、大写或增加字距的标签式排版；
- 内容区保留充足留白，通过字号、间距、分组和层级承载信息密度，避免把生产工具做成拥挤的工程监控台；
- 可使用低饱和的苔绿、泥土色、雾灰、灰紫和浅粉作为辅助色，但业务状态必须使用独立、稳定的语义色，不得随主题装饰色变化；
- 状态、告警和可操作性不能只依靠颜色表达，还需要文字、图标或形态辅助识别；
- 动效保持克制，只服务于状态变化、选中反馈、面板展开和跨对象定位；
- 不采用霓虹色、高饱和渐变、重度玻璃拟态或科幻仪表盘风格。

视觉设计需要在保持上述气质的同时，优先保证长篇产物阅读、Agent 生产过程和复杂状态信息的可读性。

第一版只交付上述浅色主题，不提供深色模式。视觉实现仍需使用语义化主题变量组织背景、文字、边框、交互与状态颜色，避免组件直接依赖固定色值，为后续增加深色主题保留扩展能力。

## 13. 当前能力基线

现有系统已经具备或部分具备：

- 模板列表和模板输入字段读取；
- 动态输入表单；
- Case 创建、运行和人工恢复；
- production、test、all 环境切换；
- Case 列表；
- Agent 泳道；
- Turn、消息路由和工具行为展示；
- 产物版本和行级 Diff；
- Issue 展示；
- 返修 editable/frozen 可视化；
- 交付门禁展示；
- waiting_human 提示和回答；
- 上下文快照和 provider 错误等诊断数据。

当前模型配置存在一个需要在产品化时修复的实现缺口：

- `scenario.yaml` 已为每个 Agent 声明 `model`；
- 当前 Real Pi 实际统一读取全局 `PI_MODEL_ID`；
- 当前 Provider 在 Adapter 中固定为 `deepseek`；
- CaseRunner 创建 Pi Session 时尚未传递 `agentConfig.model`；
- 因此模板声明的模型目前没有真正决定 Agent 的运行模型。

当前主要产品差距：

- 所有能力集中在单一页面，信息层级不清；
- 缺少以用户待办和当前结果为中心的工作台；
- 缺少独立的模板理解和选择体验；
- 创建任务交互较弱；
- Case 列表缺少搜索、筛选和清晰摘要；
- 用户需要阅读泳道才能判断整体进度；
- 产物、Issue、返修和门禁之间缺少直接关联；
- 异常和恢复仍偏工程提示；
- 原始工程信息与用户信息混在一起；
- 现有页面更适合回放验证，不适合作为完整生产操作台。

## 14. 与后续编排 UI 的关系

本文档当前首先细化单个 Forge Case 的 UI 产品化。

后续内置预定义编排器后，相关 UI 需求也继续写入本文档，但应建立独立章节，至少包括：

- 预定义流程列表；
- 创建流程运行；
- 流程阶段进度；
- 阶段与 Case 的关系；
- 上下游产物流转；
- 流程级异常和恢复；
- 下游失效传播；
- 最终流程交付。

当前单 Case UI 的任务、状态、产物、Issue、门禁和诊断概念，应尽可能能够被未来编排 UI 复用。

预定义编排器进入产品后，在主导航增加独立“流程”入口；在此之前不预留空白或不可用导航项。

## 15. 阶段性成功信号

- 内容生产操作者无需 CLI 即可创建并运行一个 Forge Case；
- 内容生产操作者可以通过选择模板、填写输入和确认配置三步完成任务创建；
- 草稿自动保存状态清晰可见，保存失败或存在未保存内容时不会静默丢失；
- 用户进入任务详情后可以快速判断当前状态和下一步；
- 用户无需阅读 Agent 泳道、Turn 或工具日志即可判断任务状态、待办和当前结果；
- 用户可以找到当前有效产物和最终交付产物；
- 用户不会把最新创建但仍在审核、已拒绝或已替代的版本误认为当前有效结果；
- 用户在当前阶段无法通过 UI 覆盖或人工修改任何已有产物版本；
- 用户可以理解审核问题、返修范围和问题是否验证关闭；
- 门禁失败时，用户可以定位到具体阻断来源；
- waiting_human 可以在 UI 内完成闭环；
- 失败或恢复状态不会只显示不可理解的内部错误；
- 使用者仍然能够通过高级视图获取脱敏后的完整运行证据；
- UI 不产生与数据库状态相冲突的第二套状态。
- 当前 UI 不能永久删除已启动任务，归档后仍可恢复查看完整证据。
- 回收站草稿可以恢复，第一版不会自动删除，也不提供永久删除或清空回收站。
- 默认工作台和搜索不展示归档任务，用户可以显式包含归档或只查看已归档任务。
- 用户可以安全暂停和恢复运行中任务；停止后的任务不能原地继续。
- 异常任务是否可恢复由系统依据执行证据判定，用户不会面对危险的强制重试选项。
- 用户可以通过阶段和步骤状态理解真实进度，不会被虚假的百分比或预计时间误导。
- 用户可以基于已有任务创建带来源关系的新任务，而不会复制或污染原任务的运行证据。
- 模板更新不会静默改变草稿或已启动任务，用户可以在升级前查看差异并重新确认配置。
- 所有使用者都能找到高级功能，同时不需要接触高级功能也能完成常规生产任务。
- 使用者可以从相关对象直接进入高级功能，不需要先切换全局界面模式。
- 使用者可以查看 Provider、模型目录和连接状态并选择 Agent 模型，但无法通过 UI 接触连接凭据。
- 用户可以通过工作台、筛选和任务详情准确发现待处理、异常和已完成任务，无需独立通知体系。
- 用户可以通过状态摘要快速筛选统一任务列表，且无法通过拖拽或界面操作伪造任务状态。
- 第一版主导航保持为工作台和模板中心，创建、详情、模型与诊断能力均可从相关上下文进入。
- 用户可以自由创建和复用任务标签，但标签不会替代结构化状态或影响任务执行。
- 用户可以复制产物正文，或下载纯文本、Markdown 和模板声明的原始类型。
- 用户可以在专门的只读阅读模式中阅读、搜索和定位长篇产物，并按需进入版本比较。
- 用户可以在同一执行记录界面中理解 Agent 生产过程和产物演进链，并在两者之间双向定位。
- 用户可以从模板卡片快速判断用途和可用性，并按需进入详情或高级配置证据。
- 用户可以查看完整且脱敏的持久化执行证据，同时无法接触模型隐藏思维链或任何秘密。
- 用户查看最新进度时可以自动跟随，查看历史证据时不会被新事件抢走位置。
- 用户可以在桌面和常见笔记本宽度下完成完整生产操作，手机端不属于第一版目标。
- 用户在工作台、任务详情和模板中心可以感知到一致的暖色、克制、圆润的编辑器式视觉语言，同时不牺牲生产信息的辨识度。

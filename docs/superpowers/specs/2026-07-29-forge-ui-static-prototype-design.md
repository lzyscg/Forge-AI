# Forge UI 静态交互原型设计

**日期：** 2026-07-29  
**状态：** 方案已确认，等待书面规格复核  
**实现性质：** 独立、可丢弃的本地视觉原型，不代表真实 Forge 能力已经完成

## 1. 目标

制作一个无需安装依赖、无需启动服务、可直接双击打开的 Forge UI 静态原型，用模拟数据验证以下问题：

- Forge 作为内容生产工具的整体视觉气质是否正确；
- 操作者能否从工作台快速理解任务状态和待办；
- 任务概览是否能先回答“进行到哪里、现在做什么、当前结果是什么”；
- Agent 生产过程与右侧产物演进链能否在同一界面中建立清晰关联；
- 模型、Issue、返修、Diff 和验证信息是否足够清楚但不过度工程化。

原型不连接 SQLite、Pi、Forge API 或文件系统，不修改现有 `apps/web`，也不能作为 P0 功能完成证据。

## 2. 交付形态

原型放在独立目录 `prototypes/forge-ui/`：

```text
prototypes/forge-ui/
├── index.html
├── styles.css
├── mock-data.js
├── app.js
└── README.md
```

- `index.html`：语义化页面骨架、全局导航和各视图容器。
- `styles.css`：设计变量、布局、组件、状态、动效和响应式规则。
- `mock-data.js`：故事生产任务、模板、Agent、Turn、产物、Issue 和模型模拟数据。
- `app.js`：通用渲染与本地交互，不按具体业务角色写条件分支。
- `README.md`：双击打开方式、推荐视口和原型边界。

所有资源本地内嵌或使用系统能力，不加载 CDN、远程字体、分析脚本或网络图片。

## 3. 页面与核心旅程

### 3.1 产品壳层

顶部保留品牌、全局搜索、环境选择和“新建生产任务”入口；左侧主导航只展示“工作台”和“模板中心”。任务详情使用面包屑返回工作台，不新增长期主导航。

模板中心只做一层浅展示，用于验证主导航和模板卡片气质；不实现模板导入、编辑和版本管理流程。

### 3.2 工作台

工作台是默认视图，包含：

- 问候标题与一句当前工作摘要；
- 运行中、待处理、草稿、已完成四个状态摘要卡，点击后筛选任务；
- 搜索、状态筛选、环境筛选和紧凑视图切换；
- 统一任务列表，突出任务标题、模板、真实阶段、更新时间、待办原因和当前 Agent；
- 至少六条不同状态的模拟任务，覆盖运行中、等待审核、返修、草稿、失败和已交付。

点击主模拟任务进入任务概览。

### 3.3 任务概览

默认先展示产品结论，不直接铺开执行日志：

- 任务标题、状态、模板、环境和只读冻结提示；
- 当前阶段横幅，说明正在发生什么和下一步；
- 四段式生产进度；
- 当前有效产物摘要与正文片段；
- Issue、返修和交付门禁摘要；
- Agent 与实际模型列表，运行中模型显示为已冻结；
- “查看执行记录”作为主要下钻入口。

### 3.4 执行记录

执行记录采用三栏桌面布局：

1. 左侧为本次任务的 Agent 列表，展示职责、实际模型和当前状态；
2. 中间为调用生成过程，以时间顺序展示 Turn、路由、工具行为和产物生成节点；
3. 右侧为产物演进链，串联 `v1 → Issue → 返修 → v2 → verified → delivered`。

交互规则：

- 点击 Agent，仅强调该 Agent 的相关 Turn；
- 点击中间 Turn，右侧自动选择对应版本或 Issue；
- 点击右侧版本、Issue、返修或验证节点，中间定位并高亮相关 Turn；
- 版本节点可切换“正文 / Diff”；
- 模型胶囊可展开查看 Provider、Model、来源和冻结状态；
- 不展示模型隐藏思维链、Token、Authorization Header 或模拟凭据。

## 4. 模拟数据

主任务采用一个知乎故事生产案例，包含四个数据驱动的 Agent：

- 大纲设计 Agent；
- 章节执行包 Agent；
- 正文写作 Agent；
- 质量审核 Agent。

每个 Agent 的名称、职责、颜色、模型和事件均来自 `mock-data.js`，渲染器不对这些名称作分支判断。主链至少包含：

- 6–8 个 Turn；
- 3 个产物版本；
- 1 个 blocking Issue；
- 1 条受控返修指令；
- 1 次 verified 结果；
- 1 组交付门禁；
- 2 个 Provider、4 个实际模型示例。

## 5. 视觉系统

视觉方向继承冻结需求和用户提供的 Claude Design 参考图，采用“温暖编辑器 + 纸张阅读感”，不采用数据库搜索返回的紫色 AI 仪表盘方案。

### 5.1 色彩

```css
--canvas-terracotta: #CE7657;
--canvas-terracotta-deep: #B95F43;
--shell: #F3F0EA;
--surface: #FFFDF9;
--surface-muted: #F4F0E8;
--ink: #24211E;
--ink-muted: #6B645C;
--line: #DED7CD;
--accent: #C96548;
--action: #1F1D1A;
--success: #3F765C;
--warning: #A8652A;
--danger: #A84640;
--info: #6D6687;
```

品牌色只用于选中态、轻量强调和外层环境背景。业务状态使用稳定语义色，并同时配合文字、图标或形态表达。

### 5.2 字体与层级

- UI 字体：`"Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`；
- 长篇产物：`"Noto Serif SC", "Songti SC", serif`，仅用于正文阅读区域；
- 正文基准字号 15–16px，辅助文字不低于 12px；
- 栏目标签使用小字号、较大字距和大写英文辅助，不用等宽字体制造工程控制台感。

### 5.3 形态与动效

- 产品壳层圆角 26px，主要卡片 16–20px，控件 10–12px；
- 使用 1px 暖灰边框和低透明度柔和阴影，不使用重度玻璃拟态；
- 主操作为近黑实底，次操作为暖白描边；
- 动效控制在 160–240ms，只用于面板切换、选中定位、悬停和展开；
- 支持 `prefers-reduced-motion`，关闭非必要位移和滚动动画。

## 6. 响应式与可访问性

该产品面向桌面和常见笔记本，不设计手机完整操作体验：

- 1440px 以上使用完整三栏执行记录；
- 1100–1439px 压缩左栏，右侧演进链保持可用；
- 760–1099px 将产物演进链移到主时间线下方；
- 低于 760px 展示“建议使用桌面浏览”的紧凑只读布局，不产生横向溢出。

所有按钮和图标按钮具有可访问名称、可见焦点、键盘操作和不低于 40px 的主要点击高度。正常文字对比度目标不低于 4.5:1，不以颜色作为唯一状态信号。

## 7. 状态与数据流

原型只维护浏览器内存状态：

```text
mock-data.js
  → 初始任务与视图状态
  → app.js 通用渲染
  → 用户点击 / 搜索 / 筛选 / 选择
  → 更新内存状态
  → 局部重绘并同步选择关系
```

刷新页面恢复默认状态，不写 LocalStorage，不上传或读取本地文件。未知任务、版本或 Turn ID 统一回退到当前任务的默认概览，不抛出阻断页面的异常。

## 8. 原型反馈

原型中的“新建生产任务”、暂停、停止、模型修改等尚未设计的真实命令，不伪装成已经实现：

- 允许点击的演示入口以本地浮层说明“静态原型，仅展示交互位置”；
- 选择、筛选、视图切换、关联定位和 Diff 展示需要真实可用；
- 不使用浏览器原生 `alert`；
- 无 JavaScript 时展示明确的 `<noscript>` 说明。

## 9. 验收方式

实现完成后进行以下验证：

- 双击 `index.html` 可离线打开，无控制台错误和网络请求；
- 工作台筛选、搜索、任务进入、概览切换、Agent/Turn/演进链联动和 Diff 切换可用；
- 1440×900、1280×800、1024×768 三个视口无内容遮挡或非预期横向滚动；
- 键盘 Tab 顺序合理，焦点可见，图标按钮具有可访问名称；
- `prefers-reduced-motion` 下无非必要动画；
- 页面不出现凭据、隐藏思维链或真实工程 ID；
- 运行仓库现有 `npm run check`，保证独立原型没有影响现有 TypeScript 工程。

## 10. 明确不做

- 不连接真实 Forge、SQLite、Pi、Provider 目录或 SSE；
- 不替换、重构或美化现有 `apps/web`；
- 不实现三步创建流程、模板编辑、归档、回收站和设置页；
- 不实现人工修改产物；
- 不实现预定义流程可视化或编排器；
- 不实现 Electron、移动端、深色模式、鉴权或权限；
- 不把模拟交互描述为真实运行能力。

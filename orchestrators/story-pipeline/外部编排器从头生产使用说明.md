# 外部编排器：从头生产使用说明

本文用于交给一个专门的生产 Agent，让它从新的运行目录开始，自动完成一条故事生产链路。

## 一、职责边界

外部编排器负责：

- 多个 Forge Case 的串行编排；
- 输入、父记录、Case 身份和模板身份绑定；
- 原始产物、结构化 sidecar、校验报告和正式产物的落盘；
- SHA-256、Manifest CAS、锁、恢复和下游失效传播；
- 发现证据不一致时 fail closed。

故事内容的生成、审核和质量门禁由各 Forge Case 自己负责。外部编排器不应凭自己的判断改写故事内容，也不应为了让流程继续而放宽 Case 的审核结果。

## 二、运行前准备

工作目录：

```text
C:\Users\13863\Desktop\zhihu\Forge AI\Forge-AI-main
```

在工作目录创建 `.env`，不要把密钥写入命令行、日志或 Git：

```dotenv
DEEPSEEK_API_KEY=<本机真实密钥>
PI_MODEL_ID=deepseek-v4-flash
MAX_TURNS=20
```

`PI_MODEL_ID` 和 `MAX_TURNS` 可以按实际模型调整。启动前只检查变量是否存在，不要输出变量值。

确认 Node.js、npm、tsx 依赖可用：

```powershell
cd "C:\Users\13863\Desktop\zhihu\Forge AI\Forge-AI-main"
npm run check
```

## 三、必须使用新的运行目录

不要直接复用以下目录进行“从头生产”：

```text
data/story-runs/gaokao-zero-real-003
```

该目录是历史恢复验收目录，里面保存了旧模板身份、失效记录和恢复声明。新生产必须使用新的 `run_id`、新的 `run-dir` 和新的 Forge DB。

先复制生产配置，再把 JSON 中的 `run_id` 改成新的唯一值。例如：

```powershell
Copy-Item `
  data/story-runs/gaokao-zero-real-003-config.json `
  data/story-runs/gaokao-zero-fresh-001-config.json

$configPath = "data/story-runs/gaokao-zero-fresh-001-config.json"
$config = Get-Content -Raw -Encoding UTF8 $configPath | ConvertFrom-Json
$config.run_id = "gaokao-zero-fresh-001"
$config | ConvertTo-Json -Depth 20 | Set-Content -Encoding UTF8 $configPath
```

检查配置中的 `source_file`、`chapters`、`requirements` 和模板所需输入都正确。不要复制旧 run 目录中的 `manifest.json`、`forge.db` 或产物文件。

## 四、启动完整生产链路

完整链路命令如下。不要添加阶段停止参数，也不要在 ledger 完成后手动中断；让编排器自行继续到 final：

```powershell
npx tsx orchestrators/story-pipeline/src/index.ts run `
  --config data/story-runs/gaokao-zero-fresh-001-config.json `
  --mode real `
  --run-dir data/story-runs/gaokao-zero-fresh-001 `
  --db data/story-runs/gaokao-zero-fresh-001/forge.db
```

当前一章配置的阶段顺序是：

```text
outline
  -> packet-b001
  -> draft-b001
  -> ledger-b001
  -> final
```

正常情况下，命令会自动完成所有阶段并输出 `final_artifact`。不需要为每个阶段另外创建 Case，也不要把上一个 Case 的原始输出手动复制到下一个目录；编排器会通过 Manifest 和输入文件完成接力。

## 五、生产 Agent 的监控方式

生产 Agent 应持续观察命令输出和运行目录，但不要修改 Manifest：

- `[run]`：创建新的 Forge Case；
- `[resume]`：复用已有非终态 Attempt；
- `[skip]`：复用已经验证过的 Stage Record；
- `[replace]`：发现模板、输入或父版本变化，进入 replacement；
- `[story-pipeline]`：fail-closed 错误，需要停止并报告。

重点文件：

```text
data/story-runs/<run-id>/manifest.json
data/story-runs/<run-id>/raw-artifacts/
data/story-runs/<run-id>/artifacts/
data/story-runs/<run-id>/structured/
data/story-runs/<run-id>/validation/
data/story-runs/<run-id>/inputs/
data/story-runs/<run-id>/forge.db
```

## 六、成功验收标准

只有同时满足以下条件，才报告“整条链路完成”：

1. 命令退出码为 0；
2. 输出包含 `success: true` 和 `final_artifact`；
3. Manifest 中 `final_artifact_path` 非空；
4. outline、packet、draft、ledger、final 都有 delivered Stage Record；
5. 每个 Stage 的 raw artifact、正式 artifact、sidecar、validation report 都存在且 SHA-256 一致；
6. `manifest.json` 的事件链可通过校验；
7. 终稿内容等于编排器记录的正式终稿文件，不以聊天输出替代文件证据。

生产 Agent 的报告至少包含：run_id、Manifest 路径、final artifact 路径、各阶段 Case/Record ID、是否发生返修、是否发生恢复，以及最终退出码。

## 七、异常处理规则

### 1. 进程意外退出

使用同一个配置、同一个 `run-dir` 和同一个 DB 再次运行：

```powershell
npx tsx orchestrators/story-pipeline/src/index.ts run `
  --config data/story-runs/<run-id>-config.json `
  --mode real `
  --run-dir data/story-runs/<run-id> `
  --db data/story-runs/<run-id>/forge.db
```

不要删除 Manifest、Attempt、事件、锁或证据目录。编排器会先对账，再恢复或继续执行。

### 2. 内容审核失败

这是 Forge Case 的内容返修问题。等待 Case 自己完成审核/返修，或报告 Case 的状态和 Issue；不要在外部编排器中伪造 approved、delivered 或 validation 结果。

### 3. `ambiguous` 或身份不一致

停止自动生产并报告候选 Case、输入哈希、父记录和错误详情。不要按时间新旧自动选择 Case，不要手工编辑 Manifest 绕过 CAS。

### 4. 模板身份迁移错误

例如：

```text
模板身份算法已变化，需要先完成显式身份迁移
```

这通常意味着误用了历史 run 目录，或当前模板已经发生协议级变化。从头生产时应新建 run；不要直接修改旧记录中的模板身份。

### 5. API Key 或模型错误

确认 `.env` 位于仓库根目录、变量名为 `DEEPSEEK_API_KEY`，并且子进程能够读取。不要把密钥粘贴到 Agent 对话、命令参数或错误报告中。

## 八、禁止事项

- 不复用历史恢复目录做新的从头生产；
- 不删除或改写 `manifest.json`、历史 events、invalidations、失败 Attempt；
- 不手工创建 Forge Case ID 或 Stage Record；
- 不把模型原始输出直接当作正式 artifact；
- 不把外部编排器的结构校验当作故事质量审核；
- 不在没有明确授权时执行 `reconcile --apply`、`invalidate` 或人工 Case 接纳；
- 不在日志中输出 API Key、runner token 或其他凭据。

## 九、可直接交给生产 Agent 的任务指令

```text
你负责从头运行故事生产链路。

1. 使用一个新的 run_id、run-dir 和 Forge DB，不复用任何历史恢复目录。
2. 确认仓库根目录 .env 中存在 DEEPSEEK_API_KEY，但不要输出密钥。
3. 使用 --mode real 执行 story-pipeline run，让编排器自动完成 outline、packet、draft、ledger、final。
4. 不添加阶段停止控制，不手工接力，不修改 Manifest，不伪造 Case 或交付状态。
5. 如果进程意外退出，使用相同参数重跑；如果出现 ambiguous、模板身份迁移或 fail-closed，停止并报告，不要绕过。
6. 只有当命令成功退出且 final_artifact、Manifest、各阶段证据和 SHA-256 均存在时，才报告生产完成。
7. 报告 run_id、各阶段 Record/Case ID、最终 artifact 路径、退出码和任何返修/恢复事件。
```
